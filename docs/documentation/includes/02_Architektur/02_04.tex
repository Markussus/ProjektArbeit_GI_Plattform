\subNsection{1}{Simulator-Architektur}{Richard Schröder}

Das \verb|ISimulator<TConfig, TState>|-Interface und der generische \verb|useSimulationEngine|-Hook bilden die Grundlage für alle schrittweisen Simulationen innerhalb der Plattform. Mit dieser Architektur wird die fachliche Simulationslogik vollständig von der Steuerung und Darstellung entkoppelt.

% \begin{itemize}
%   \item \textbf{Generisches Interface}: Ein Vertrag, der eine einheitliche Schnittstelle für alle simulationsfähigen Maschinen (z. B. \verb|Turing-Maschine|, \verb|Endliche Automaten|, \verb|Moore/Mealy-Maschinen|) definiert. Durch die Verwendung von Generika für Konfiguration (\verb|TConfig|) und Laufzeitzustand (\verb|TState|) bleibt das Interface unabhängig von der konkreten Maschinensemantik.
%   \item \textbf{Zentrale Steuerungslogik}: Ein generischer React-Hook, der als \glqq Driver\grqq{} fungiert. Er abstrahiert die zeitliche Steuerung (Play/Pause/Geschwindigkeit) und die Synchronisation zwischen dem internen Simulator-Zustand und dem React-State. Dadurch muss die Logik für Timer, Fehlermanagement und Statusübergänge nur einmal implementiert werden und kann für alle Simulatoren wiederverwendet werden.
%   \item \textbf{Entkopplung von Logik und UI}: Die Implementierungen der Simulatoren (z. B. \verb|TuringMachineSimulator|) enthalten ausschließlich die mathematische Logik der Maschine. Die UI-Komponenten interagieren lediglich mit dem Hook, was eine konsistente Bedienung über verschiedene Themenbereiche hinweg garantiert.
%   \item \textbf{Evolution der Architektur}: Die Git-Historie zeigt eine Entwicklung von spezifischen Einzelimplementierungen hin zu einem generischen Framework. Dies reduzierte die Redundanz erheblich, als weitere Maschinentypen hinzugefügt wurden, und ermöglichte es, Verbesserungen an der Steuerungslogik (z. B. \verb|stepBack|-Funktionalität) global für alle Simulatoren bereitzustellen.

Durch die Implementierung dieser Architektur ist es möglich, eine Vielzahl theoretischer Maschinenmodelle auf einer einheitlichen technologischen Basis abzubilden. Durch die Definition des Interfaces wird eine Trennung zwischen der mathematischen Definition einer Maschine und ihrer technischen Ausführung in einer Web-Umgebung erreicht. Während die konkreten Simulator-Klassen lediglich die Zustandsübergänge und die Logik eines einzelnen Schrittes definieren, übernimmt der Hook die komplexere Orchestrierung. Er verwaltet die zeitliche Taktung der Simulation mittels Browser-Timern und sorgt dafür, dass Änderungen im internen Zustand des Simulators unmittelbar im React-State gespiegelt werden, um eine reaktive Aktualisierung der Benutzeroberfläche auszulösen.

Dieser modulare Aufbau führt zu einer Steigerung der Wartbarkeit und Erweiterbarkeit des Systems. Die Hinzunahme eines neuen Maschinentyps erfordert lediglich die Implementierung des Interfaces, ohne dass die Steuerungslogik oder die UI-Komponenten für die Play-/Pause-Funktionen angepasst werden müssen. Im Laufe des Projekts ist dieses Interface zur Vereinheitlichung entstanden; zunächst lag der Fokus auf Einzelimplementierungen der Komponenten, damit die Anwendung funktioniert. Danach wurden die notwendigen Kernfunktionen identifiziert und in das Interface bzw. den Hook ausgelagert.
